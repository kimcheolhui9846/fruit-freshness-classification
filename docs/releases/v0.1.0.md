# Fruit Freshness Classification v0.1.0 — Engineering Milestone

Approved release target: `v0.1.0`
Approved release type: `PRERELEASE`
Approved release date: `2026-08-02`

## Overview

This is the first engineering and reproducibility milestone for Fruit Freshness Classification. It packages the project as a modular, documented PyTorch research repository without presenting a trained-model benchmark or a model-performance result.

## Highlights

- Modular `src/` packages for datasets, transforms, models, losses, training, evaluation, inference, engine helpers, and utilities.
- A shared TOML experiment configuration used by the active notebook and command-line entry points.
- Training and labeled-holdout evaluation CLIs.
- A fixed-revision Hugging Face dataset compatibility loader with safe managed extraction and explicit ImageFolder handling.
- CMT classification workflow with Focal Loss, Mixup, EMA, AMP, stratified K-Fold training, checkpoint handling, and horizontal-flip TTA ensemble support.
- Windows and Ubuntu CPU repository CI, plus MIT software licensing and repository-only citation metadata.

## Installation and usage

Follow the repository-relative setup and dependency guidance in the [README](../../README.md) and [environment documentation](../environment.md). The stable entry-point contracts are:

```text
python -m scripts.train --help
python -m scripts.evaluate --help
```

The active experiment configuration is [`configs/deep3.toml`](../../configs/deep3.toml). Training requires production dataset access and writes local checkpoints; evaluation requires compatible fold checkpoints and evaluates a labeled holdout ensemble. See the [training guide](../training.md), [evaluation guide](../evaluation.md), and [configuration guide](../configuration.md) for details.

## Verified reproducibility

Same-machine clean-environment verification covered the production dataset loader, production DataLoaders, a bounded real-data CUDA CMT smoke path, checkpoint interoperability, and the labeled holdout evaluation CLI using untrained compatibility fixtures. The fixture measurement demonstrates interoperability only; it is not model-quality or benchmark evidence.

## CI

`Repository CI` runs offline on Windows Python 3.12 CPU and Ubuntu Python 3.12 CPU. It validates dependencies, imports, configuration, compilation, unit and contract tests, CLI help, and repository cleanliness. CUDA work and production dataset access are intentionally excluded from CI.

## Known limitations

- Trained-checkpoint evaluation has not been run.
- Benchmark reproduction has not been completed.
- Full notebook execution has not been verified.
