# Fruit Freshness Classification v0.2.0 — Post-Holdout Research Milestone

Approved release target: `v0.2.0`
Approved release type: `PRERELEASE`
Approved release date: `2026-08-16`

## Overview

`v0.1.0` packaged the repository as a modular research codebase without a model result. `v0.2.0` adds what happened when that codebase was used to run a pre-registered research programme: one completed canonical training run, one locked-holdout evaluation, and a six-phase post-holdout investigation whose main finding is about the limits of its own measurements.

It is still a source-only prerelease. No trained weight, checkpoint, training state, raw logit, raw prediction, log, or dataset file is distributed, and this release makes no benchmark, production-validation, or generalization claim.

## Highlights

- **Post-holdout research protocol.** The 21,486-example historical training pool was split once into 17,188 development and 4,298 locked-test examples. The locked test has had **zero model forward passes** and remains frozen.
- **Pre-registration throughout.** Every phase froze its protocol and its numeric decision rule before execution, which is why several phases were able to refute the hypothesis that motivated them.
- **A blind label audit that cleared the data.** Phase 9.5 reviewed 497 development images against a pre-committed threshold and returned `DEFECT_NOT_CONFIRMED`. The subject error rate came out *lower* than the control rate, refuting the label-noise explanation the previous phase had proposed.
- **A measured noise floor.** Three runs of one unchanged configuration gave development OOF Macro F1 of 0.901167, 0.912041, and 0.901858, so two sigma is 0.012177.
- **A deterministic training pipeline.** The pipeline previously set no random seed at all. `A_STRICT` — seeded, `cudnn.deterministic`, no autotuner, `torch.use_deterministic_algorithms` — now produces bit-exact runs, verified over two runs and confirmed independently with `sha256sum` over the checkpoint files.
- **A frozen minimum detectable effect.** `MDE_MACRO_F1` is 0.012177, derived from measurement rather than chosen. Candidates below their metric's MDE are recorded `BELOW_RESOLUTION` rather than as successes or failures.

## What the research found

**The acceptance margin was smaller than the noise.** Phase 9.6 tested stronger class-balanced reweighting against a threshold of baseline plus 0.010. The run-to-run two sigma, measured afterwards, is 0.012177. The rerun of the *unchanged* baseline scored 0.912041 — above the threshold the intervention missed at 0.910182.

**One class produces 90.56% of the metric's instability, and it is the class the research was trying to fix.** `freshpotato` has a run-to-run standard deviation of 0.0739 against 0.0181 for the next-noisiest class. Of its 347 development images, 183 are misclassified in every run and only 62 are correct in every run.

**Determinism removes measurement noise but not seed-to-seed variation.** Fixing a seed pins one draw from the same distribution rather than narrowing it, so bit-exactness did not lower the measurement floor.

**Finer-grained metrics do not buy power.** Three successive designs — aggregate Macro F1, then the target class's F1, then per-image tests within one pair of runs — were each defeated by the same fact. The last was calibrated directly: a per-image McNemar test fires on four of six run pairs that share an identical configuration. What varies between runs is a property of the run, so the effective sample size is the number of runs.

H1 is recorded `CLOSED_BELOW_RESOLUTION`: resolving the observed effect needs 71 to 212 GPU hours. That is neither "exhausted", which the evidence does not support, nor "keep trying", which the arithmetic prices out of reach.

## Changes since v0.1.0

- Canonical training completed once and was evaluated once against the fixed 5,372-example internal holdout: 0.955510 top-1, 0.903737 macro F1. The holdout shares byte-identical images with the training pool — 1,618 of its 5,372 rows — so this figure is higher than it would be on distinct images; on rows without such a copy Top-1 is 0.9414. The figure is unrevised. See [the dataset duplication audit](../dataset-duplication-audit.md).
- `scripts/train.py` gained epoch-boundary resume through a trusted local `training_state.pt`, which validates immutable run identity before applying state.
- `src/utils/determinism.py`, `src/utils/measurement_floor.py`, `scripts/verify_determinism.py`, and `scripts/diagnose_freshpotato_instability.py` were added.
- Experiment configurations are validated by lineage: a config naming a registered ancestor must change exactly its registered factor, and an unregistered parent is rejected rather than skipped.
- Run manifests moved to `schema_version` 2 with a `determinism` block. An unseeded run records its seed as null rather than omitting the field.
- The test suite grew from 119 to 452 tests, including repository contract tests that fail if a frozen protocol document is edited.

## Known limitations

- The reported model result is one internal fixed holdout, not an external benchmark, production-validation result, or generalization claim.
- `freshpotato` is unstable, not merely weak. A single run's score for that class is unreliable; see the [model card](../model-card.md).
- Training-run reproducibility was not verified before Phase 9.7. Every result recorded before it came from a pipeline that set no random seed.
- Determinism is established for one host and one pinned software stack. Independent-machine reproduction is not verified.
- No post-holdout candidate was advanced. The programme closed because its measurement floor exceeded the effects available to it, not because a candidate succeeded.
- Full notebook execution is not verified, and generic unlabeled image inference is not implemented.
