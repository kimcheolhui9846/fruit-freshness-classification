# Holdout evaluation

## Canonical command

Evaluate the saved cross-validation ensemble from the repository root:

```powershell
python -m scripts.evaluate --config configs/deep3.toml --checkpoint-dir weights
```

`--config` defaults to `configs/deep3.toml`. `--checkpoint-dir` is required: evaluation never falls back to the notebook's legacy machine-specific checkpoint path, never searches `weights/` automatically, and never chooses a partial ensemble. Relative paths are resolved from the repository root; a caller may explicitly provide an absolute checkpoint directory.

## Checkpoint contract

The active experiment has `cross_validation.n_splits = 3`. Before it loads the Hugging Face dataset or any model, the entry point requires this complete set in ascending fold order:

```text
<checkpoint-dir>/best_model_fold1.pt
<checkpoint-dir>/best_model_fold2.pt
<checkpoint-dir>/best_model_fold3.pt
```

The filename template remains the existing `src.utils.paths.build_fold_checkpoint_path()` contract. It is not a CLI/configurable template, so callers cannot supply a malformed template. A missing directory, a path that is a file, an empty directory, or one or more missing expected fold files raises an explicit error and stops evaluation; extra files are ignored. No checkpoint directory or artifact is created by this command.

## Evaluation flow and parity

`scripts.evaluate` is a script-level wrapper around the notebook's existing final labeled holdout path:

| Responsibility | Reused implementation |
| --- | --- |
| Config and CUDA-first device selection | `load_experiment_config`, `resolve_device` |
| Runtime parity | configured `torch.backends.cudnn.benchmark` value |
| Dataset cleanup, remapping, split, and RGB handling | `load_fruit_freshness_dataset` |
| Deterministic holdout preprocessing | `build_validation_transform` |
| Holdout batching | `build_holdout_dataloader` |
| Fold model construction and state loading | `load_fold_models` |
| Raw-logit ensemble, horizontal-flip TTA, and counts | `run_ensemble_holdout` |

The script derives `num_classes` from the processed training split, wraps the existing held-out `test` split, loads folds `1..K`, and prints the notebook-compatible result:

```text
Final Holdout Acc: <correct / total>
```

It does not change label cleaning, the deterministic 80/20 split, transforms, model construction, checkpoint loading semantics, ensemble averaging, horizontal-flip dimension, metric calculation, or fold order. The notebook has no explicit evaluation seed; the script adds none. It writes no prediction file, figure, result JSON, log, dataset cache, or checkpoint.

## Evaluation versus generic inference

This project currently defines only a labeled Hugging Face holdout evaluation contract. It does not define a stable generic unlabeled-image input, preprocessing/output schema, submission format, or prediction-artifact location. Therefore Phase 5.4 intentionally adds `scripts/evaluate.py` only and does **not** add `scripts/infer.py`. A future inference entry point should be designed separately after that input/output contract is explicit.

## Operational boundary

Evaluation needs the project runtime dependencies and Hugging Face dataset access described in `docs/environment.md`. It also needs fold checkpoints generated by a compatible training run. Phase 5.5 rerun executed the production command on the full 5,372-example holdout with temporary untrained compatibility fixtures; this verifies the evaluation path, not model quality. See [reproducibility.md](reproducibility.md) for that evidence and its limitations. Automated tests use temporary files and patched dataset boundaries to verify CLI, checkpoint validation, orchestration order, and import safety without downloading data or evaluating a production model.
